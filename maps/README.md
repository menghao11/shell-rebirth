# 弹壳轮回 · LDtk 地图

两关的战斗房间改由 [LDtk 1.5.3](https://ldtk.io) 工程 `maps/shell-rebirth.ldtk` 描述。游戏在 Phaser **3.90.0** 里解析这份 JSON（不升级引擎）。教学关和铁皮屋仍是原来的单屏房间。

这是地图数据接入，不是上线说明。发布与否以仓库的合并和 Pages 部署结果为准。

## 打开

1. 安装 LDtk **1.5.3**（其它版本会改 `jsonVersion`，校验会失败）。
2. 打开 `maps/shell-rebirth.ldtk`。世界是 Free 布局，每一块是一个房间模块，同一行的模块拼成一关里的一个房间。
3. 本地玩：在仓库根目录起静态服务（不要用 `file://`，浏览器会拦截 `fetch`）：

```bash
python3 -m http.server 8765
```

浏览器打开 `http://127.0.0.1:8765/game/`。

## 层

网格 **32×32**，和 `DK.M`（1 米 = 32 逻辑像素）一致。层从上到下：

| 层 | 类型 | 怎么用 |
|---|---|---|
| `Gameplay` | 实体 | 玩家、敌人、出口、商人、篝火、Boss、人质、补给 |
| `Decor` | 实体 | 掩体、沙漠道具、爆炸桶 |
| `Collisions` | IntGrid | `0` 可走，`1`（Solid）墙。人和子弹都撞这层 |
| `Ground` | IntGrid | `1` 土/沙，`2` 主路（浅色），`3` 点缀（草或碎石）。`0` 不铺，相机里是虚空 |

关卡字段（选中整块关卡，不是实体）：

| 字段 | 含义 |
|---|---|
| `stage` | `1` 废弃前线，`2` 沙海 |
| `role` | 房间种类：`Trench` `Crater` `Camp` `Mine` `Shop` `Boss` / `Canyon` `Ruins` `Depot` `Oasis` `BossDesert` |
| `variant` | 同一种房间的随机变体，从 `0` 开始。变体 1 是变体 0 的左右镜像，支路换到另一侧 |
| `optional` | 勾上表示隐藏支路。主路不经过它也能到出口 |
| `region` | 玩家走进这块时屏幕上的区域名 |

实体（锚点都是中心 `0.5, 0.5`，坐标是逻辑像素里的中心点）：

| 实体 | 字段 |
|---|---|
| `PlayerStart` | 无。每张拼好的图一个 |
| `EnemySpawn` | `kind`：`charger` `rifle` `sniper` `heavy` `camel` `jumper` `grenadier`；`wave` 从 1 开始 |
| `Exit` | 无。生成器把触发区放在模块外侧门洞。人走进去进下一房间 |
| `Merchant` / `Rest` | 军火商 / 篝火。商店房两个都放，当局是哪种就用哪个 |
| `Boss` | 铁砧或沙鲸的站位 |
| `Hostage` | 人质 |
| `Supply` | `kind`：`Heal`（+25 生命）或 `Grenade`（手雷 +1）。只在本局里生效，不写进存档 |
| `Prop` | `prop` 必须是游戏里已有的键（`cover_sandbags`、`s2_oil_tank` 等） |
| `Barrel` | 爆炸桶 |

门洞高 **8 格 = 256px**。这是按实测留的：玩家半径 13、冲刺约 109px、跳兵横跳 95px，8 格走廊中心到墙约 128px，横跳和侧向冲刺都放得下。骆驼冲锋约 323px，带骆驼的房间有一条至少 11×6 格的直线空地。手雷射程 280px，掷弹兵附近有约 10×6 格的空地。

斜俯视沿用原来的脚点：道具 `depth = 脚底 y`，墙画在角色后面（`depth -50`），避免大墙把人挡住。相机不调用 `setBounds`（原点在左上角且缩放不是 1 时，Phaser 会把世界挪偏），跟随是手写的，滚动限制在地图内。

## 编辑墙、刷怪、出口

1. 在 `Collisions` 上涂 `1` 就是墙，擦掉就是路。门洞两侧模块的开口要对齐，否则路会断。
2. 主路格子的 `Ground` 用 `2`，玩家能顺着浅色走。
3. `EnemySpawn` 放在离墙至少一个自身半径的空地上，`wave` 对应该房间在 `game/src/data.js` 里的波次（第一波是 `1`）。种类和数量不要少于那一波，多出来的点不会刷。
4. 出口模块勾上关卡用途后，把外侧门洞留成可走。运行时会在门洞上放一扇关上的门，清完房间才打开。
5. 隐藏补给放在 `optional` 的模块里。不要把敌人出生点放进支路，否则主路清不完。

改完在 LDtk 里保存。工程本身就是 JSON，不需要另存一种格式。

## 保存、导出、构建、重载

```bash
node tools/export-ldtk.js
```

这一步会：

1. 用官方 `LDtk 1.5.3` schema 校验 `maps/shell-rebirth.ldtk`。
2. 检查两关每个变体：出生点不在墙里、主路到出口/Boss、支路补给真的不在主路上、敌人点对得上 `data.js` 的波次、骆驼/跳兵/手雷有空地。
3. 把同一份 JSON 写进 `game/src/ldtk-data.js`（`fetch` 失败时的备用，例如直接打开文件）。

然后刷新游戏页。页面会先请求 `../maps/shell-rebirth.ldtk`，成功就用这份；失败才用嵌入的副本。所以本地服务器上，保存后即使忘了导出，刷新也能看到刚保存的墙。提交到仓库前仍要跑导出，保证两份一致。

`node tools/gen-ldtk.js` 会**用蓝图重写整个工程**。手改过 ldtk 之后不要跑它，除非你打算丢掉手改。

`node tools/overview.js` 会重画 `maps/overview.png`。

主路是「出发 → 战斗 → 短喘息 → 再战斗 → 出口」，支路是补给，不是必经。下一波敌人要等玩家走进约 640px 才出现，避免隔着整张图对射。超过约 900px、且不在冲锋/跳跃中的敌人本帧不跑 AI。

墙体合并成矩形静态刚体，不是一格一个物体。地面烘成一张 RenderTexture，像素量封顶约 600 万，避免按设备像素把大图烘爆。这两处是结构上少建对象，不是测过的帧数提升。

随机：`DK.run.mapSeed` 只活在这一局的内存里，不写入 `dankelunhui_meta_v1`。同一局里重进房间用同一个变体。

没有改成长、剧情、音乐、Boss 血量和伤害、升级倍率、存档字段。震屏仍然关掉；受击闪白和短暂停顿还在。
